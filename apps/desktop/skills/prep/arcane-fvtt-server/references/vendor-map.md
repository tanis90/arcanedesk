# 云厂商速查(接入引导 / 安全组 / 控制台密钥对)

skill 不做任何云厂商集成:不调 OpenAPI、不存云凭证、不按厂商写分支代码。本表
是**话术与诊断文案**的事实源,按接入时①问的厂商取用。

## 安全组放行 30000/TCP(部署期并行引导,不是失败兜底)

默认安全组几乎只开 22/3389+ICMP——放行 30000 是**几乎必然要做的一步**,在镜像
下载的一两分钟窗口里并行引导用户去开,不等验证失败才提。

| 厂商 | 控制台路径 | 规则内容 |
|---|---|---|
| 阿里云 | 云服务器 ECS → 实例 → 详情页点"安全组"名 → 配置规则 → 入方向 → 手动添加 | 自定义 TCP,端口 `30000/30000`,源 `0.0.0.0/0` |
| 腾讯云 | 云服务器 CVM → 安全组 → 入站规则 → 添加规则 | TCP / `30000` / `0.0.0.0/0` |
| 华为云 | 弹性云服务器 ECS → 安全组 → 入方向规则 → 添加 | TCP / `30000` / `0.0.0.0/0` |
| 其他/自管 | 通用指引:找"安全组 / 防火墙 / 入站规则",放行 TCP 30000、来源所有 | 同上 |

话术带一句为什么:来源放开到所有是因为玩家来自任何网络,安全边界在 FVTT 账号
密码体系。22 端口超时的兜底提示也走同一张表(把 30000 换成 22)。

诊断口诀:宿主机 loopback(V2)通而公网(V3)不通 ≈ 必是安全组——docker 发布
端口绕过 ufw/firewalld,主机防火墙这个变量基本可排除;出现这个组合直接回本表
话术,不排查别的。

## 控制台密钥对规则(兜底路径的坑)

三家国内大云行为一致:**自动生成的 .pem 只在创建密钥对时下载一次、平台不保存、
丢了只能重建**;**给已有实例绑密钥对必须先关机/停止,绑完开机生效**。

| 厂商 | 控制台路径 | 关键坑(要说给用户) |
|---|---|---|
| 阿里云 | ECS → 网络与安全 → 密钥对(或实例详情 → 全部操作 → 绑定密钥对) | 左上角**地域必须和实例一致**否则看不见密钥对;"创建密钥对"的 .pem **只此一次下载**;"导入密钥对"粘的是我们给的**公钥**;**绑定前实例先停止**,开机生效;新绑定自动替换旧密钥对(旧的失效,正常) |
| 腾讯云 | CVM → SSH 密钥 | 创建后**自动下载** .pem,平台不保存;**绑定/解绑需关机** |
| 华为云 | ECS → 密钥对 | 同构:创建时下载私钥;**绑定/替换需停机** |
| AWS / Oracle / GCP | 仅**创建实例时**选/建 keypair | 已有实例**不能补绑**;.pem 丢了只能换钥匙或用厂商控制台网页终端救——这类用户直接引导用他们手里的 .pem |

## 下载源(镜像 tar.gz / mod 索引)

跟 app 的 region flavor 走,不跟服务器物理位置:cn 一律 OSS 北京(阿里云 ECS
同区域时自动切内网 endpoint `arcane-package.oss-cn-beijing-internal.aliyuncs.com`,
经元数据服务 `100.100.100.200` 探测 region),intl 一律 R2
(`dl.arcanedesk.app`)。服务器侧统一 curl 模板:

```
curl -fL --retry 5 --retry-delay 2 -C - --connect-timeout 10 -o <file> <url>
```

`-f` 让 HTTP 错误直接失败、`-C -` 断点续传(不可变对象,续传安全)。下载目录用
`/var/lib/arcane/staging/`(不落 /tmp,很多发行版它是 tmpfs),`docker load`
后即删。
