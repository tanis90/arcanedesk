# 从模块构建文件生成安装包

使用主 skill 已验证的随包 Node 和管理器。构建器与原生依赖已经随 skill 携带；不安装 npm、
不下载编译器、不寻找开发者仓库、不复制或改写生成器。

交互预算：只生成安装包最多需要用户提供文件这一次；明确的生成请求就是对本地新建产物的
授权，不再询问技术参数。生成后安装沿用本地安装的一次计划，不用构建授权覆盖安装授权。

```text
bundle-inspect --input <构建文件绝对路径>
```

该检查只读文件，返回 id、version、输入大小和 SHA256；它只检查输入类型和身份，完整内容
校验由共享构建器执行。支持 format 为 `arcane-module-bundle`、schemaVersion 为 1 的已准备
输入。普通法术 JSON、原始第三方包或描述资料不符合该协议时明确说明，不能靠改字段冒充。

在系统临时目录选择本次任务独有的新目录，告知生成的位置，然后执行：

```text
bundle-build --input <同一inputPath> --out <新目录/module> --zip <新目录/module.zip> --expected-sha256 <inputSha256>
```

使用本次检查的哈希，输入变化就停止重新检查。工具校验内容和文件路径、生成合集与清单，
再打包 ZIP；不执行内容脚本、不联网、不改写现有 Foundry。输出目录必须新建或为空，ZIP
不能覆盖已有文件。失败留下的目录用于排错，不得当成成功安装包。

成功后报告模块版本和 ZIP 路径。用户要求安装时，使用返回的 archive 路径进入
[local-module.md](local-module.md)，将 local-inspect 的 ZIP 哈希与构建回执的 archive.sha256
核对后准备安装计划。不要把输入 JSON 的哈希当成 ZIP 哈希。

完整描述、素材和合集仍属于用户内容，不上传到 GitHub、镜像或日志附件。构建成功不表示
内容获得公开分发许可，也不代表新增法术/职业已通过游戏内 QA。
