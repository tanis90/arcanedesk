# MinerU 样式重建与标注

MinerU（mineru-open-api）的 md 输出**不含字体颜色、斜体、底色**；`-f json` 输出只有块级数据：`bbox`、`page_idx`、`text`、`text_level`、`type`（text / image / page_number / page_footnote）。PDF 里的视觉样式（朗读蓝字、DM 提示绿底框等）需要用替代信号重建。

## 用户交互预算

**恒定 0 次提问**。样式语义的确认发生在用户发起任务时（「把朗读段标出来」本身就说明了语义）；拿不准样式含义时，把它写进第五步的人工确认清单随报告交付，不打断流程。信号够不着的段落不猜、不问，列入清单。

## 前提

- 模组已按 arcane-module-reader 拆成章节库（`章节/*.md` + `_原始解析/`）。
- 样式类别有限且样式语义明确（比如「蓝色斜体=朗读」「绿底=DM 设计建议」）。用户没说清时，从人工确认清单反推，不为猜不清的样式动工。
- **版面 JSON 只有精准模式能出**：`-f json` 属于 `mineru-open-api extract`（需要已配置 Token）；免 Token 的 `flash-extract` 只出 md，没有 bbox，走不了信号 B。Token 未配置时先按 arcane-module-reader 的持久化流程配置，或只做信号 A 并在报告里说明。

## 第一步：探测（不要急着实现）

1. 拉少量页面的 JSON 看结构：`mineru-open-api extract "模组.pdf" -o <临时目录> -f json --pages 3-9`（`extract` 支持 `-f md,json` 与 `--pages 1-10,15` 页段语法）。服务器对同一文件有缓存，重复拉取很快。
2. 如果用户能提供原文截图或粘贴：注意粘贴乱码（字体映射坏）意味着「直接解析 PDF 内容流拿颜色」这条真值路线有风险，列为兜底。
3. 全书 JSON 值得留一份到 `_原始解析/<模组名>.content-list.json`，后续几何分析都靠它。

## 第二步：两类替代信号

### 信号 A：语义锚点（适用于「朗读文」这类有固定引导语的样式）

通读全文，找样式的**引出规律**。例如朗读段几乎总由「向玩家阅读以下文字：」类引导语引出。用 grep 统计引导语出现次数和全部变体，确认规律稳定后，规则为：引导语之后连续的段落是目标文本，到明显的 DM 指令段为止。

**边界必须逐条人工判定**，常见坑：

- 引导语可能嵌在 DM 指令段末尾（指令段本身不标）；
- 一句话可能被插图从中劈开（拆成两个 callout，插图留在原地）；
- 引导语之后可能紧跟多条目标段落（如祈祷词、对话行也属于朗读）；
- 存在无引导语的可疑段落（NPC 大段台词、标题下的描述段）——**不要猜**，列入人工确认清单。

### 信号 B：bbox 版面几何（适用于「绿底栏」这类有固定版式的样式）

边栏是内嵌框，文字比正文**右缩进固定量**。算法：

1. 从全书 JSON 按 `text_level` 找到候选标题块；
2. 每页正文基线 = 该页所有非标题 text 块的最小 `bbox[0]`（左右页边距不同，必须按页归一化，不能跨页用绝对值）；
3. 偏移 = 标题 x0 − 页基线。

实测信号非常干净：真边栏偏移 +22~28pt，正文小节 +2~5pt，两类完全分离。落不了类的异常值（如 +64，可能是另一种颜色的框）列入人工确认清单，不要硬归类。

### 兜底方案 C：直解 PDF 颜色（通常不值得）

用 Node + pdfjs-dist 读 PDF operator list 抓文本填充色/底色矩形。两个前置验证，任一不满足就放弃：

- PDF 必须有真文本层（扫描件 + OCR 层没有字形颜色）；
- 文本层 ToUnicode 映射不能坏（坏了就只能按坐标和 MinerU bbox 几何对齐，工程量翻倍）。

## 第三步：标注形式

Obsidian 原生 callout，只改 `章节/` 呈现，不动 `_原始解析/` 原文：

- 朗读段 → `> [!quote] 📖 朗读`
- DM 设计边栏 → `> [!example] 🎲 DM 设计思路`（**保留原 `##` 标题**，只包正文，维持文档大纲导航）

callout 的标签不是定死这两套——按模组实际的样式语义换（脚本有 `--quote-header` / `--sidebar-header` 参数），但 callout 类型保持 quote/example 不变，剥除核验的状态机只认这两个类型。

App 阅读器不支持 callout 时会退化为引用块 + 一行标签，不影响阅读。

## 第四步：安全写入管线（必须遵守）

数据与逻辑分离：先把人工判定结果写成数据 JSON（区间行号 + 每区间起始文字前缀断言；边栏写标题 + 正文段数 + 后续内容断言），再跑 `scripts/mark-apply.mjs`：

```bash
# 数据格式见 scripts/mark-data.example.json;Node 用 ARCANE_FVTT_NODE
"$ARCANE_FVTT_NODE" scripts/mark-apply.mjs <资料库绝对路径> <数据json路径>
```

脚本三阶段，缺一不可：

1. **先全部断言，再动笔**：校验每个区间的起始前缀、前后必须为 空行/标题/插图、区间互不重叠；任一失败整体中止，一个文件都不写。
2. **备份后写入**：整个 `章节/` 复制到 `_备份/章节-标记前-<时间戳>/`；同一文件内**从底部往上**应用编辑（避免行号漂移）。
3. **写后核验**：状态机剥除 callout（只在 `> [!quote]`/`> [!example]` 开启的块内剥 `> ` 前缀——章节顶部导航行本身可能也是 `> ` 开头的引用行，无差别剥会误判），与备份**逐行比对**，必须完全一致。

## 第五步：人工确认清单（交付的一部分）

信号够不着的段落不猜，列成清单让用户对着 PDF 一眼确认，每条注明：位置（章节）、疑点、当前处理（未标记/按推测标记）。确认后的修正是小范围 edit，不用重跑管线。

## 最终报告写清

标注数量（两类各几处、覆盖哪些文件）、备份路径、核验结论（剥除比对逐行一致）、人工确认清单、以及 MinerU JSON 的留存位置。
