### M2 — 2026-09-07

- 每模式增加 SessionRegistry，每个 resident 会话保留独立 AgentHost；界面新建和打开会话不再调用原 host 的 abort/detach。目录在实例创建时固定，打开历史时恢复其目录。
- ModeHostController 快照捕获实际会话实例；命令上下文增加 sessionId/taskId；前端按会话、任务隔离事件和回执。停止旧任务不能作用于新任务。
- 任务执行状态从 busyByMode 移到各 host，运行开始和终止发出 task_state。SDK 的 agent_end/settled 不再直接清掉有任务身份的前端 busy。
- 验收：desktop typecheck 通过；全量 297 项测试通过；随后增加的 renderer 事件隔离测试及 registry 定向测试共 5 项通过。
- 测试使用真实 AgentHost/ModeHostController 和可控 session 替身，证明应用生命周期与路由；真实 SDK 并发、Electron 完整交互由 M4/M8 验证，不能将模块测试等同于产品终态验收。
- 后续：M3 接入恢复快照、导航竞态和阅读状态；M4 完善 SDK 停止/正常完成竞态、输入接收及任务协调器抽离；M5 需要把现有按模式统计的 telemetry 上下文改成按会话隔离；M7 完善删除准入锁、实例回收和退出恢复。

### M3 — 2026-09-07

### M4a — 输入登记与执行协调 — 2026-09-07

- 抽出 TaskCoordinator 与 InputJournal。输入持久登记后即回执；commandId 与内容摘要保证重复回执不重复执行，变更同一命令内容会拒绝。附件准备发生在幂等检查之后。
- 协调器管理任务与待处理输入，执行中的补充通过 SDK steer 入队；结束边界未被消费的输入由同一任务接着处理。停止先清队列；旧任务停止命令不影响后续任务。
- 真实 SDK 实验发现：停止时 user message_start 可以发生而没有后续模型调用。因此区分“进入上下文”和“助手流开始”，只有后者标记已交给助手；不将入队或写入历史当成已消费。
- 前端保存带 commandId 的 outbox，捕获会话目标后才调用 IPC；失去回执时提供同 ID 重试。发送状态和消费状态分别展示。恢复日志标记未终止任务为 interrupted，不自动重放。
- 验收：全量 desktop 311 项测试通过；随后增加磁盘写入失败测试，协调器定向 7 项通过。真实 Pi SDK 测试 2 项通过，分别验证补充在下一模型边界只消费一次、停止清除未消费队列。测试 provider 为进程内受控流，不连接外部服务。
- Electron 页面验收通过，增加“回执不确定→重试仍用同一 commandId”检查；最终 typecheck 与源码边界检查通过。
- M4b 仍需实现结构化提问/回答、待处理项恢复和任务内模型变更延后。完整任务恢复、日志压缩及失败后继续交互仍在 M7/M8 核对，M4 整体尚未完成。

### M4b — 结构化提问与任务模型边界 — 2026-09-07

- 两模式提供 request_user_input 工具；协调器持久记录问题、回答与状态，任务等待回答时仍可停止。回答同时校验会话路由、taskId、attentionId 和 commandId，重复回答复用回执，过期问题拒绝回答。
- 当前执行进程存活时，快照恢复问题卡片和回答草稿；进程重启后未解决问题标记 interrupted，不假装保留了原工具等待栈。恢复时先安装问题与输入状态，再重放新事件，避免把已回答状态倒退回 pending。
- 前端显示明确任务状态、选项与自由文本回答入口；回答尝试身份保存在工作区。已有可选写操作确认加入 waiting_user 状态及快照，停止会拒绝并解除其等待。
- 运行中的模型选择持久记录为下一任务配置，当前任务在接收时捕获模型变更边界；即使模型调用尚未启动，也不会被随后选择的模型改写。界面标明“下一任务使用”。
- 验收：desktop 全量 317 项测试通过；随后新增可选审批运行态测试 1 项通过；最终 typecheck、source boundary、Markdown 链接检查通过。
- 真实 Pi SDK 3 项测试通过，新增“真实工具等待回答→携回答进入下一模型调用→原 taskId 完成”。Electron 页面验收新增跨模式恢复问题和回答草稿、回答归属正确，并继续通过已有现场恢复/重试场景。
- 后续仍按 M5–M8 推进跨会话活动、资源调度、生命周期及完整规格审计，不将本阶段验收等同于整个终态已完成。

### M5a — 活动摘要与持久阅读边界 — 2026-09-07

- 新增 ActivityCenter，只派生任务摘要，不修改执行状态。按会话保留未读、阅读游标、待处理项及通知消费键；同模式和跨模式任务互相隔离，普通输出不重排列表。
- 主进程先发正文事件再更新活动摘要；高频输出合并发布，活动流使用独立 epoch/seq。会话列表带活动摘要，新增受信 IPC 快照和已读确认入口。
- 已读确认要求窗口在前台可见、阅读位置在底部，并以页面实际安装的正文游标校验；后台、历史位置及迟到确认不能清掉更新的结果。已读不清除完成或失败状态。
- 通知消费先持久化后派发；问题和现有审批按具体项去重，等待状态本身不重复提醒。恢复快照只校准摘要，不重新派发历史提示。写入失败保留内存活动与错误状态，抑制未持久确认的通知。
- 验收：新增 7 项活动模块测试通过，desktop 全量 325 项测试通过，typecheck/source boundary 通过，原有 Electron 会话恢复与问答验收通过。新增测试覆盖同模式并发、阅读竞态、通知持久去重、重启校准、500 个流片段合并、磁盘故障和摘要不含正文/工具参数。
- 限制：这是主进程及 IPC 基础验收。跨模式活动界面、阅读分界、系统通知授权与点击策略、遥测会话隔离仍待 M5 后续实施；尚不能宣称后台结果已经对用户可见。日志压缩和生命周期的一致性继续在 M7/M8 核对。

### M5c — 会话遥测隔离 — 2026-09-07

- 每个 resident AgentHost 持有独立遥测上下文，隔离活动回合、重试、工具计时、技能读取与摘要。所有会话仍共享唯一 writer、uploader、授权状态、安装身份和递增事件序号，不增加上传实例。
- 会话与回合继续使用本次启动内的随机关联 ID；实际会话/任务 ID 不进入事件。主进程接收输入后向目标 host 记录，任务终态由 TaskCoordinator 驱动遥测结算；SDK 片段结束和点击停止本身不提前结算。
- 共享 Foundry runtime 以异步调用上下文携带发起会话与模式，队列内等待不改变归属。无会话的原调用继续走全局观察入口；不改变 runtime 执行及错误语义。
- 关闭授权清空全部会话的统计状态，再次开启重新发布各会话的模型维度，跳过中途任务以免把半段记录当完整结果。释放会话回收其统计上下文，不关闭共享 writer。
- 验收：新增 4 项测试，覆盖同模式相同工具 ID 的不同耗时、不同重试、独立摘要、统一事件序号、授权切换、释放隔离和共享 Foundry 队列归属。desktop 全量 329 项测试、typecheck/source boundary 及活动 Electron 验收通过；真实 Pi SDK 的输入/停止/提问回归 3 项通过。
- 后续：M5 尚需系统通知设置、派发策略与点击恢复；M6–M8 的调度、生命周期及终态审计仍未完成。

### M5d — 系统通知策略与点击返回 — 2026-09-07

- 通用设置新增默认关闭的系统通知开关，写入成功后生效。启用后仅在窗口不在前台时派发完成、失败或待处理通知，标题为会话名，正文仅为状态标签，默认静音。
- 消费 ActivityCenter 已持久去重的新提示，不补发关闭期间或恢复历史的提示。已读完成、已回答问题、删除会话及关闭开关时撤掉对应通知；过期任务的通知点击不能跳转到新任务。
- 仅显式点击通知才显示/聚焦窗口。目标先留在主进程，页面就绪后一次性领取；页面重建丢失即时信号时仍可返回目标。通知派发或设置存储失败不改变任务执行。
- 验收：新增 4 项通知策略测试通过；desktop 全量 333 项测试、typecheck/source boundary 通过。Electron 活动验收扩展实际设置 IPC、点击返回及点击后页面重建恢复，继续通过既有跨模式/未读/草稿场景。
- 边界：测试使用原生通知替身，不在用户系统弹出测试通知。已验证策略、Electron 页面与 IPC 链路，尚未证明各平台系统通知中心实际展示；系统展示、平台限制及退出/重开入口继续纳入 M7/M8 审计，不将替身测试等同于原生系统展示验收。

### M6a — 执行额度与可取消排队 — 2026-09-07

- 两模式共享 FIFO ExecutionScheduler，默认同时推进 2 个任务；`ARCANE_TASK_CONCURRENCY` 可设为 1–16 的整数，无效配置退回 2。选择会话不改变队列顺序。
- 任务接收后登记排队状态，获得额度才进入执行。未开始任务取消后显示 cancelled，保留输入取消状态且不会启动；已执行任务收到停止请求后，直到实际 prompt 退出才归还额度。
- 结构化提问及已有可选确认释放执行额度，回答持久接收后重新排队，获取额度后才恢复工具调用栈。多个待答项共享恢复闸门，不重复占位。
- 核对安装的 Pi agent-loop 与 tool-definition-wrapper：工具默认可并行，批次含 sequential 工具时顺序执行。生产提问和可等待确认的工具已有 sequential 标记，本阶段保留并据此验证释放额度不会让同批后续工具越过等待点。
- 验收：新增 4 项执行调度测试与 2 项真实 Pi SDK 测试；desktop 全量 339 项测试通过，typecheck/source boundary 通过。调度测试覆盖双任务占位、FIFO、取消、幂等释放、多问题恢复及停止后延迟归还；SDK 测试覆盖回答后排队不运行后续工具/模型，以及恢复排队中停止。已有可选确认测试增加额度释放检查并通过。
- 活动 Electron 验收继续通过，并增加新任务 queued 事件切换 taskId、排队文案及 cancelled 终态检查。SDK provider 为进程内受控流，不访问外部模型。
- 限制：执行额度不是资源锁。同工作区 shell/文件、Foundry 页面导航/截图/脚本的冲突协调仍待 M6 后续；暂不宣称已完成受控资源隔离或全量并发性能验收。
