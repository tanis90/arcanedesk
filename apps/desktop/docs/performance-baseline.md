# 多会话响应性能基准

日期：2026-09-07。结论：下述 Windows 受控基准通过 spec §11.2 的响应时间门槛；这不是其他设备、物理屏幕呈现或完整应用生命周期验收。

## 设备与负载

- Windows 11，build 22631，x64；Intel i7-11700，16 个逻辑核；63.77 GiB 内存。
- Electron 44.0.0 / Node 24.18.1；1200 × 850 隐藏 offscreen 窗口，关闭硬件加速，60 Hz 动画帧。
- 16 个任务由真实 ExecutionScheduler 同时准入，备团与战斗各 8 个；每会话 10,000 条原生历史和 5,000 条已消费输入回执，历史显示窗口 100 条。
- 每秒 160 个累计文字更新、32 个任务状态变化；TaskCoordinator 日志和 ActivityCenter 摘要在独立临时目录实际持久化。
- 内容为普通文字及 Markdown 列表/强调。任务的 prompt 与资源等待由受控过程产生，不调用模型或外部工具；历史由原生 SessionManager 在内存中建立，初次读盘不属于缓存切换指标。

## 测量方法

使用实际 renderer、preload、AgentHost、TaskCoordinator、SessionProjection、HistoryIndex、ActivityCenter 和原生 SessionManager。测试夹具提供 IPC 路由和受控 prompt。先预热目标会话，再触发真实导航按钮，同模式和跨模式各 60 次；其他任务持续产生更新。

选中反馈按第一帧的选中样式计时，内容按目标会话恢复完成的第一帧计时。状态校准另外要求安装本次请求返回的执行侧快照，不以缓存显示代替校准。进度和状态延迟从执行侧事件发送前计时，检查事件游标及对应正文/状态已经反映在 DOM，再于动画帧记录。用户切走后的事件不作为当前正文的呈现样本。

这是第一动画帧中的 DOM 状态测量，不包含显示器扫描或窗口管理器最终呈现。末尾额外保持运行 16 秒采样；结果按排序后的 nearest-rank P95 计算。验收要求两类导航各 60 样本且均符合门槛、缓存未命中为零、进度至少 100 样本、状态至少 25 样本。

## 结果

完整设备信息、样本数、P50、P95、最大值及进程内存见 [原始结果](performance-baseline.json)。最终基准运行时未同时执行本任务的其他测试。

| 指标 | P95 | 门槛 | 样本数 |
| --- | ---: | ---: | ---: |
| 选中反馈，合并两种导航 | 31.5 ms | 100 ms | 120 |
| 缓存内容显示 | 31.5 ms | 300 ms | 120 |
| 执行侧最新快照校准 | 62.9 ms | 1,000 ms | 120 |
| 普通进度呈现 | 60 ms | 500 ms | 190 |
| 任务状态呈现 | 103 ms | 500 ms | 37 |

同模式选中/内容 P95 为 33.1 ms，校准 62.9 ms；跨模式分别为 27.1 ms、61.1 ms。120 次切换均命中缓存。

采样末尾主进程 working set 为 825.2 MiB，renderer 为 248.7 MiB；各自记录的峰值为 1,032.5 MiB 和 258.8 MiB。该负载同时保留 16 个活动任务及其长历史，不能用一次工作集采样推导长期内存上限或泄漏结论。GC、数据建立阶段与系统负载会影响结果。

## 本次发现并修复的问题

首次补齐历史输入回执后，快照仍包含所有回执正文，触发缓存容量估算的遍历上限；60 次同模式切换均没有缓存命中，缓存场景门槛因此未通过。该记录见 [修复前结果](performance-before-receipt-paging.json)，来自修复前产品代码 `021c653`。当时基准仅包含 60 次同模式切换，不据此进行跨模式前后时延比较，也不将“缺少缓存样本”描述成响应时间超限。

现在只返回页内消息对应的已处理回执正文，以及尚未消费的输入。所有已接收命令身份仍随快照返回，前端据此清理不在当前页的 outbox 回执；不需要用户再点击重试，也不会丢失服务端幂等身份。原输入记录与日志没有删除。

## 重复执行

在仓库根目录运行：

```powershell
node apps/desktop/test/benchmark-conversations.mjs apps/desktop/docs/performance-baseline.json
```

该命令启动独立隐藏 Electron 窗口，使用临时 userData，不操作用户正在使用的应用或真实世界。完成后退出，失败返回非零状态。与其他压力测试分开运行；原始结果会被指定输出文件覆盖。单测、历史恢复和 UI 验收仍需分别执行，基准不能代替它们。

仍未由本基准覆盖：完整 production main 启动组合、物理系统通知/托盘交互、不同设备和平台、后台长期驻留、模型供应商或真实 Foundry 的执行耗时、大型图片/图表/单条超大工具输出。完整规格审计继续进行。
