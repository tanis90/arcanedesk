# 创建角色 benchmark 代表性审查

状态：npc_wizard 首次配对预检已完成；两组均结束但未通过预设火球术准备检查，尚未完成执行就绪验收。整体决策与迭代进度仍以
[唯一技术方案](foundry-prep-play-technical-plan.md#1416-创建题代表性审查与其他工具收敛)为准；
运行协议见 [benchmark 文档](prep-benchmark.md)。本文件细化审查方法，不另立产品技术方案。

## 要回答的问题

创建工具比裸 JS 慢，可能有两种解释：真实常见任务本来就适合短脚本，专用工具价值有限；
或者当前题目提前消除了真实任务的困难，无法衡量工具价值。
先验证任务代表性，再决定是否保留、调整或不默认暴露创建工具。暂停围绕复制 Wolf 继续增加能力，
不为证明工具有用而故意提高难度，也不预设现有工具可以解决更复杂的任务。

## 保留的简单题及其边界

现有题直接指定 dnd5e.monsters、精确名称 Wolf，要求复制并设置 Actor／原型 Token 名称。
它代表“已经选好来源，复制改名”，应继续保留，不能用新难题替换后隐藏其负面结果。

已知局限：每次使用唯一名称，没有预置同名角色，实际上未覆盖“已有则不重复”的分支；
不需要组合种族、职业、等级和法术数据；验收记录来源却未以来源匹配作为通过条件，
也没有验证完整内容保留。旧题的成功仅在其已实现验收范围内成立。

## 用户确认后的真实任务

> 创建一个五级的人类法师 NPC，18智力，其他分配要合理，法术保证有火球术。给他装备上一根长棍。

用户已取消盾牌，允许选择匕首或长棍等熟练武器；本题固定为长棍，保持两组要求一致。
不再设置盾牌熟练／施法冲突的澄清或验收项。
用户已明确选择 NPC 卡（Actor type=npc）。按五级法师施法能力配置人类 NPC，
不要求玩家角色的完整种族／背景／职业升级流程，不把施法者等级等同于 CR。

直接使用自然语言意图，不预先补入合集名、英文资源名、字段路径、UUID、调用顺序或配卡答案。
如真实对话此前已确定规则版本、角色类型或内容来源，应把那段上下文同时交给两组，
不能人为制造重新搜索。测试世界使用隔离对象，保持双方可访问的资源与初始状态一致。

这题从现成 Actor 复制变为组合 NPC 数据。它可能涉及资源发现、属性分配、施法者等级、
HP／熟练／施法资源、法术及装备的实际配置。困难是否存在、发生在哪里，由轨迹证明，
不把增加角色数量或文本长度本身当成有意义的难度。

## 实跑前需要定下的验收口径

以下是待落实的协议要求，不是已经完成的验收器，也不在此替 DM 作规则裁定。

- 固定世界系统／规则版本及可用资源。使用已确认的 NPC 数据形态，不能按玩家卡完整建卡规则判分。
- 智力最终值为 18；其他属性允许多种合理分配。先约定适用分配规则或允许 DM 裁定，
  不将某一套精确配点当作唯一答案，也不偷偷预设某种规则必然能满足 18 智力。
- NPC 的人类身份和五级法师施法能力应有实际数据支撑，不能只检查显示名称；
  不强制嵌入完整职业、种族或背景 Item，不要求法师职业升级自动化。
- 验证实际 HP、熟练与施法资源配置的一致性；先确认这些字段在当前系统的有效表达。
  施法者等级五级不代表 CR 5，也不直接套用玩家职业等级对 NPC 所有数值作验收。
- 火球术须为正确法术内容，并满足约定的可用状态与施法资源条件；物品栏仅有同名条目不算充分。
  其他法术的数量和选择范围在运行前明确，接受多个合法配置。
  不擅自追加完整玩家法术书或升级选法流程作为要求。
- 长棍确实添加并装备，角色具有相应武器熟练；不能只检查物品名称，不额外添加盾牌。
- 检查非目标内容未被误改。若测重复执行，明确预置同一角色及预期行为，不能只在题面写幂等要求。

合理澄清不是失败。预先准备两组共享的 DM 答复口径；未预见问题标为待裁定，记录人工介入，
不由测试者临时给某一组提示。报告分别列总流程时间、模型执行时间与人工等待，
不把测试者的世界核验计入模型耗时。

不要求所有职业动作自动化可执行；其稳定实现仍在本期范围外。
不为了跑通题目修改 auto pack。发现包侧缺口按 [TODO 纪律](todo.md)记录背景、需求、改造思路和边界，
能力不可用与模型使用失败分别记账。无法建立有效验收的字段不能默认为成功。

## 对照与归因

保留简单复制题，另加本题，升级 suiteVersion，旧数据不覆盖。
沿用同供应商、模型及设置的新会话配对；先做一次协议预检，确认任务可验收后再决定重复次数。
2026-09-08 用户明确要求开始测试，首次采用阿里云 qwen3.7-plus，各臂一次；
新套件版本 prep-npc-intent-draft1，单次上限 300 秒，与原简单题 120 秒分开记录。
默认六题集合不变，新题通过 --cases=npc_wizard 显式运行。

首次协议预检使用 2014 规则，允许模型自行选择未指定内容；不要求固定配点、完整玩家法术书或职业动作自动化。
自动检查 NPC 类型、人类身份、智力 18、智力施法及施法等级 5、满额一至三环法术位 4/3/2、
无更高环法术位、正 HP 且满血、可准备使用的三环火球术及敏捷豁免／8d6 火焰／成功减半／消耗法术位活动、
一根已装备长棍和无盾牌。此为数据级就绪检查，不实际释放法术，不声称包侧执行集成通过。
基础验证器 3 项测试通过；NPC 属性分配、HP／CR／熟练一致性、其他法术及长棍有效熟练由保存的完整数据人工复核。
自动通过不能替代人工复核。成功与失败角色均暂时保留供核验，使用含组别的唯一测试名，防止后一组复用前一组结果。

JS 组与工具组获得相同用户需求、资源和 DM 答复。生产模式中的路由提示差异必须披露，
当前测的是完整工作流，不是只改变一个创建工具的实验。
本题还会用到搜索、读取、授物和更新，不能将整题收益全部记到 actor_create 名下。
若后续要决定只删除 actor_create，应另做仅移除该工具并同步合理路由的对照，保留其他能力。

记录模型在哪里花费额外步骤：选资源、识别系统字段、组合角色、参数纠错、回读或修复；
区分推理 token、模型响应轮数、工具耗时与端到端耗时，不将任务总耗时称为思考时间。
先核验正确率和实际可用性，再评价响应是否达到 DM 可接受水平；不事后设定有利于某组的速度门槛。

## 决策规则

| 实验观察 | 决策方向 |
| --- | --- |
| 真实常见任务中 JS 快、正确且少纠错，工具无额外价值 | 不继续无谓优化；评估不提供或不默认暴露创建工具 |
| JS 在真实需求上反复探索／失败，工具确实减少困难 | 补齐对应 benchmark，围绕被证实的困难演进 |
| 两边都困难，现有工具没有改善 | 不能据此证明工具值得保留；重新评估能力边界及维护成本 |
| 工具慢在自身参数表达／强制额外步骤 | 与任务困难分开记录，避免把接口问题包装成模型能力不足 |

一条真实示例足以证明旧套件有覆盖缺口，不足以证明此类请求在实际备团中的频率。
最终保留决策结合真实使用频率、可接受等待、错误后果与维护人天，不追求每一题都由工具获胜。

## 首次预检结果

[记录](prep-npc-wizard-pilot-results.json)，原报告 benchmark-1788857680729。
裸 JS 179.24 秒、19 次调用；工具组 152.11 秒、26 次调用。无工具结果错误、供应商错误或超时，
两组模型都报告完成，但自动验收均在火球术 prepared 状态失败，其余八项基础检查通过。
工具组未调用 foundry_actor_create，不能把整题差异记到创建工具名下。

裸 JS 有 18 次 browser_evaluate；轨迹包含资源搜索、NPC 等级／CR／熟练字段反复探索及修改。
它写入旧 system.preparation 对象，当前 system.prepared 仍为 0。
工具组通过结构化搜索／授物／读取／更新配合 3 次 browser_evaluate 完成；
最终回复声称已准备法术，但实际 prepared 也均为 0。它还在最终文字中把定身类人和法术反制写成了错误环位，
存储的 Item 环位则正确，须将回复错误与数据错误区分。

只读复核：两组 NPC 派生施法等级均为 5（均自行嵌入法师职业 Item），智力 18、熟练 +3、
火球术 DC 15、法术位 4/3/2，长棍已装备。两组角色和隔离 fixture 暂时保留，未实际释放火球术。
NPC 的 prepared=0 与 App／原生实际能否施法不是同一结论；当前只能认定未达到预注册准备状态要求，
不能声称已证明两组无法施法。后续须确认 NPC 就绪语义，若修改验收则升级版本并保留本次原判定。
长棍原始 proficient=null，不能据此认定缺乏熟练；其有效攻击熟练仍需在系统派生数据层复核。
未进行完整世界前后快照，不宣称全面证明没有修改任何非目标内容。

本例已经证明旧简单复制题遗漏了真实的数据配置困难；尚不能证明现有工具解决了这些困难。
单对 152／179 秒不构成稳定提速证据，两组共同的就绪问题更优先。此次不修改产品工具或 auto pack。
