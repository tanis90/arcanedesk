# Desktop 激进删减：唯一技术方案与进度

日期：2026-09-08。状态：执行中，按下方里程碑记录。

基线：`0.4.3-06aad629` → main `5cef239fff540bcf0b7e9f64a571b909c3086323`。实施工作区：`arcanedesk-design-rules`，当前分支 `docs/multi-session-design-rules`。

**本文是本轮迭代唯一有效的技术方案、范围清单和进度入口。** architecture.md、spec.md、acceptance-audit.md 及此前评审只作基线或历史证据；与本文冲突的要求停止生效。新决定、实施结果、验证记录和试用反馈只在本文更新，不再另建并行方案或审计状态表。

## 1. 工作态度与决策规则

> 如果试用时没有任何地方让用户觉得不好用、需要加回一点功能，就说明删除可能还不够激进。

顺序固定为：质疑需求 → 删除功能／流程 → 简化剩余实现 → 提速 → 自动化。没有明确 ROI 就不做；已经写了代码、已有测试、删除更难、未来可能需要，均不是保留理由。

- 删除是默认动作，不通过换名字、换框架、改成可配置或保留隐藏开关来延续旧机制。
- 不以“可能存在竞态”证明需求。先说明具体用户损失，再决定唯一执行条件。
- 功能加回必须来自具体试用问题：当时要做什么、哪里失败、造成什么影响。先判断是否只需一个更小改动，不自动恢复原机制。
- 不把真实数据破坏当作删减程度指标。对话、项目文件、用户输入和真实边界仍按下述契约保护；允许放弃已明确列出的体验与恢复保证。
- 代码和针对已删除机制的测试、文案、类型、IPC、规格要求一起删。保留剩余用户行为的测试，不为维持旧测试重建机制。

## 2. 最终产品行为

### 会话、归档和删除

- 对话文件是会话存在的唯一依据；文件丢失即视为会话删除，关联数据不承担恢复职责。
- 归档用于收纳。先发送后归档，已发起工作继续执行；提交和压缩路径不检查归档或导航文件健康状态。
- 保留侧栏置顶、项目分组、标题搜索、重命名、归档／撤销／恢复及已归档页。归档页保留恢复入口；不因其只读外观增加后端提交围栏。
- 删除不要求后端确认“已归档、导航正常、任务空闲”。停止写入者后删对话文件，再清关联数据，崩溃残留启动对账清理。删除确认只说明记录不可恢复、项目文件不删，不解释内部流程。
- 删除入口沿用现有已归档页，正常运行中的归档按钮规则本轮不额外扩展；这不改变删除后端允许负责停止任务的职责。
- 导航枚举读取磁盘摘要并合并 resident host 最新信息，不为了列侧栏而初始化两个模式的执行环境。空会话列表提供新建入口。

### 切换与阅读

- 切换直接请求最新快照，不先渲染旧缓存。重新打开会话显示最新内容，不恢复旧阅读像素位置或卡片展开状态。
- 当前视图内用户主动阅读旧内容时，不被流片强制拉到底部；保留历史分页、回到底部和草稿附件。
- 未读只是粗粒度“有新进展”：成功打开会话即清除，后台新进展再点亮。删除精确阅读确认与“上次读到这里”分隔线。
- 需要用户回答的标记由活任务决定，不因清除未读小点消失。
- 成功同步静默，加载明显延迟或失败才提供必要反馈；不显示最后确认时间、锁等待、内部输入阶段。

### 执行、通知与退出

- Foundry 和项目文件系统均无应用级资源锁，不改成读写锁、局部锁或串行队列。接受多个任务操作同一目标的冲突可能性，不承诺多调用事务隔离。
- 保留上游工具本身的内容检查、实际结果及错误。移除资源锁不改变工具超时的事实：超时不证明外部动作未发生，不自动重放写操作。
- 保留任务并发调度和等待用户时释放并发槽；锁与执行额度是不同机制。
- 停止中不把新输入接受成即将取消的旧任务补充，原输入保留。该条件只由 TaskCoordinator 执行。
- 系统通知仍默认关闭、只在后台、当前运行期内存去重、点击才聚焦。启动恢复不重发历史通知；活动数据写失败不再阻止通知。
- 正常关闭隐藏到托盘；托盘创建失败则进入退出。显式退出不二次确认、不显示进度／取消按钮、不为退出重新打开窗口。
- 退出用一条 best-effort 收尾路径：停止接收新任务，发出停止请求并保存必要状态，默认总预算 2 秒，到时退出。不是用户配置项；不等待资源租约，不无限等待。超时不承诺外部动作完成或回滚。

## 3. 信任边界和职责

```text
renderer ──① IPC──> main 编排
                        │
                        ├── SessionRegistry：host 生命周期、加载／删除协调
                        ├── TaskCoordinator：任务、输入、提问、停止、运行期去重
                        ├── AgentHost：SDK 调用适配
                        ├── ActivityCenter：内存活动摘要与最小重启摘要
                        │       同进程协作区：公开动词，不重复验参／镜像状态
                        ├──② 磁盘：对话、未消费输入、元数据、草稿
                        └──③ SDK／子进程／页面调用
```

边界按实际风险校验，通道或可信数据结构已保证的内容不重复检查。例如 IPC 只收会话 ID、主进程解析可信路径后，内部不逐层检查同一路径。

| 条件 | 唯一责任位置 | 保留理由 |
| --- | --- | --- |
| 请求来自授权界面、参数和目标可解析 | IPC 边界，已有通道保证则省略同一检查 | 避免越权或操作错误目标 |
| 路径归属、工作目录及文件实际读写结果 | 磁盘边界 | 不删任意文件，不改在错误目录执行 |
| 模型凭据和上游调用结果 | SDK 适配边界 | 无法执行时给出明确结果 |
| 删除中的会话不再接收新工作或重新注册旧 host | SessionRegistry 生命周期入口 | 避免删除文件后被旧写入者重新创建 |
| 输入不能归入 stopping 的旧任务 | TaskCoordinator | 避免返回已接受却直接取消新输入 |
| 同一运行期同命令不执行两遍 | TaskCoordinator 内存 Map | 避免即时重试重复副作用 |

AgentHost 审批逻辑不再读取并推动 TaskCoordinator 内部状态，使用其公开入口。非边界 assert 或内部执行检查必须能对应具体后果和唯一 owner，否则删除。停止接口报告自身结果，调用层不再读 busy 重复裁决。

## 4. 最小持久化

| 内容 | 保存方式及消费者 |
| --- | --- |
| 对话正文、工具结果、历史 | 现有 Pi 对话文件；唯一会话存在依据 |
| 已接受未消费输入及附件 | 每会话 `config/pending-inputs/<sessionId>.json`，内容为列表，整体替换；重启展示中断内容供用户重发 |
| 用户模型选择 | 现有会话元数据中增加字段，覆盖 deferred pending_model 与缺凭据的 _currentModelRef；重开/驱逐后恢复 |
| 标题、置顶、归档 | 现有导航元数据，不扩展为第二套任务数据库 |
| 草稿与待重发内容 | 现有 IndexedDB，保留用户内容，不存阅读锚点和展开状态 |
| 重启中断摘要 | ActivityCenter 只低频保存必要任务身份／状态；不保存流片游标、退休 epoch 列表、精确阅读及通知账本 |
| commandId/fingerprint、活提问 resolver、运行状态流转 | 内存，host 结束后消失 |

未消费输入先保存再回执接受，消费后移除；空列表可删除文件。直接复用小型可靠整体替换写入，不另建日志、版本化 checkpoint 或通用事务框架。文件损坏隔离后继续使用并告知，不永久阻塞会话。

旧 outbox 重启后恢复为待检查内容，与 pending 输入按旧身份合并展示，不覆盖独立草稿。用户重发生成新 commandId；不支持跨重启旧身份重试，不承诺跨重启幂等。旧提问卡不恢复、不接受重启后的补交回答；已写入对话的回答仍可查看。

不自动续跑、不从空 pending 列表推导任务未中断。SDK 已收到输入与本地清理之间仍可能有不确定窗口；只展示待用户检查内容，不靠新增事务保证完全一致。

启动对账是一处启动流程，按域调用幂等清理函数即可，不要求新增通用 StartupReconciler 框架。成功枚举现有对话后清理孤儿关联数据；扫描失败不视为全部文件消失。renderer 在 IndexedDB 可用后完成其关联清理。

旧任务 journal 只做一次受限迁移：从可读旧记录提取未消费输入和模型选择；目标保存成功后移除活动旧文件，坏文件隔离，不阻塞使用。没有旧文件就不执行迁移。删除日志不再回放，以真实对话文件为准。迁移不自动执行任何任务，不引入长期双写或双读取体系。

## 6. 保留范围与明确放弃

保留：多会话执行与正确路由、导航功能、草稿附件、未处理输入、原生对话记录、历史分页、活提问、任务停止、并发额度、通知偏好和基本通知、错误详情、现有遥测隔离、离线模块构建/安装能力、工具真实边界。

明确放弃：精确重启现场、旧提问恢复、跨重启命令幂等、旧快照秒开、像素位置及卡片恢复、精确已读、资源互斥、通知持久消费保证、可取消退出、退出无限等待、页面自动立即重试。

不通过预留开关继续提供这些能力。用户试用后确实遇到困难，按第 9 节记录并只加回最小必要部分。

## 8. 验证与交付

每批运行相关类型、源码检查和针对剩余行为的测试。接口变化同步改 main、preload、types、renderer；删除的模块和只服务其内部机制的测试一起移除。

必要验收场景：

1. A/B 会话同时执行、切换、停止，消息和回执不串会话；新建、跨模式和跨项目导航可用。
2. 同一运行期重复提交同一命令只执行一次；停止中输入不被假接受；连续多条未消费输入重启后都可查看并作为新请求重发。
3. 重启不续跑、不恢复旧 resolver；模型选择含缺凭据与待应用两种情况，释放 host 后仍记得。
4. 删除后对话文件不存在，不能被旧 host 写回；中途结束进程后关联数据能清理；扫描目录失败不误删；项目文件不受影响。
5. 无锁条件下不同任务能够直接调用工具；重复写同一目标不承诺隔离，错误如实反馈，超时写入不自动重放。
6. 切换直接显示最新快照；输入中的草稿附件保留；当前向上阅读不会被流片拉走；重新打开回最新；历史前后翻页可用。
7. 成功打开清未读、后台新进展再点亮；待回答标记不被误清。通知只响应当前运行期事件，不因重启补发，不因摘要写失败被阻塞。
8. 托盘正常关闭/恢复；托盘失败可退出；显式退出受 2 秒预算约束，无取消条、无重新弹窗。模拟回调不冒充真实系统点击。

集成时运行现有仓库命令：`npm run verify`。试用包用 `npm run dist:dir --workspace arcane-desktop`，并按现有 package verifier 的实际入口核验产物。遇到本机依赖或外部条件缺失，记录具体未执行项，不声称全通过，也不为解决构建条件顺带发布或推送。

性能只记录点击到有效最新内容、事件到显示的实际时延及使用体验，不要求缓存命中，不沿用旧“缓存显示”指标。未测不报数；没有试用痛点不因基准噪音重新加缓存。

交付条件：删除清单覆盖完整、剩余行为测试通过、可运行试用产物、本文进度真实更新。P8 完成可以交给用户试用，不能提前将 P9 标完成。

加回不是恢复旧模块的授权。比如切换真的慢，先定位耗时；阅读真的困难，再决定需要哪一种最低成本记忆。不能直接拿回旧快照缓存、资源锁、日志或阅读协议。

若试用没有任何需要加回之处，安排一次继续删除审查：检查仍保留的通用配置、缓存、状态映射、独立文件和恢复分支，而不是将“没有投诉”解释为恰好删够。
