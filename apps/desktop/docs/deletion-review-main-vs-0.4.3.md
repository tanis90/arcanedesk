# main 相比 0.4.3 的第二轮删除审查

> 历史审查记录。用户于 2026-09-08 接受本文全部删除建议，已纳入 [本轮唯一技术方案与进度](simplification-plan.md)。下文“候选”“未共识”等表述为确认前历史，不再单独维护。

日期：2026-09-08。基线：`0.4.3-06aad629` → 当前本地 main `5cef239fff540bcf0b7e9f64a571b909c3086323`。

方法：先质疑需求，再删除功能或流程，最后才谈优化。已有实现或测试不构成需求依据；收益不清楚时不默认保留。本文是新增删除建议，不自动视为双方共识，不修改产品代码。已对齐事项见 [共识文档](design-review-consensus.md)。

## 范围与证据

核对 Git 增量、生产调用路径、存储读写及现有性能记录。主要覆盖桌面多会话主进程、renderer、IPC 和配套状态模块；另检查了增量中的遥测、页面加载及离线模块构建相关材料。没有运行性能实验或产品测试，不宣称测得删除后的速度、内存收益，也不以代码量直接推断 ROI。

不重复计入：删除 WAL、任务 journal 替代、snapshotCache、Foundry 锁、归档提交围栏、重复断言、模型选择持久化、侧栏不启动两个 host、showPanelCommand 空壳及 recoveryBarrier 死入口。下列涉及它们的项目是可继续整块删除的范围扩展，明确注明依赖。

## 1. 删除项目文件系统资源锁

**质疑的要求：同一项目中的工具操作必须由应用统一串行化。**

证据：[agent-host.js:858](../src/main/agent-host.js#L858) 的 coordinateWorkspaceTool 为操作加入整个 cwd 的资源键，再加入具体文件路径；resource-coordinator.js:49（历史文件，已删除） 按父子路径判冲突。这使同项目不同文件的操作、包括读取，也可能互相等待。该锁是 0.4.3 之后新增的。

建议：删除这层资源仲裁，不替换为更精细的文件锁。跨多个工具调用的“读取→思考→写回”并不受当前单调用锁保护；项目目录内工具实际访问的所有外部路径也不能由 cwd 一把锁完整代表。

删除后失去：应用主动防止部分并发文件操作的能力；两个任务改同一文件仍可能冲突，这是明确接受的取舍，不宣称无风险。保留工具自身的文件校验及错误返回，不扩展删除到上游编辑工具的内容匹配机制。

可连带删：coordinateWorkspaceTool、文件资源规范化及 Pi 路径拼写适配、占用者等待、资源等待文案。与已确定的 Foundry 无锁合并后，应用级 ResourceCoordinator 及仅为锁保留资源生命周期的接入可整体清理。任务自身的完成/取消仍保留。

这是新的候选，不以已共识的 Foundry 无锁自动授权文件系统无锁；也会使原来“把路径怪癖移入适配器”的整改不再必要。

## 2. 删除精确已读确认与“上次读到这里”分隔线

**质疑的要求：侧栏未读标记必须证明用户的焦点、位置和事件版本都已精确读到最新内容。**

证据：[activity-center.js:183](../src/main/conversations/activity-center.js#L183) 校验 focused、visible、atBottom、runtimeEpoch、seq，更新 readRevision/readKey 后立即 flush；[activity-view.js:74](../src/renderer/conversations/activity-view.js#L74) 插入阅读分隔线、补偿滚动高度并调度确认 IPC。

建议：取消精确阅读回执。保留粗粒度“有新进展”小点，成功打开会话时清除，后台新进展再次点亮。需要用户回答的标记独立由当前任务决定，不随小点一起清除。

删除后失去：精确断言用户已看到哪条消息、精确未读分隔线；不失去查看对话、任务进展及待回答提示。

可连带删：activity:read 的游标确认协议、readKey/firstUnreadKey、分隔线 DOM 插入与高度补偿、相应错误路径。不是把它换成另一套更简单的精确游标协议。

## 3. 删除跨会话／跨重启的像素阅读位置与展开状态恢复

**质疑的要求：重新打开会话，必须回到同一条消息的同一像素位置，并恢复每张工具卡和思考块的展开状态。**

证据：[chat.js:297](../src/renderer/chat.js#L297) 遍历 DOM 保存 anchor、offset、expansions；installSnapshot 为旧锚点额外请求 around 历史页，处理锚点失效及滚动修复。现有 performance-with-metadata.md 记录过恢复 followLatest 状态造成停留旧页的问题。

建议：重新打开会话默认显示最新内容。保留当前页面内用户主动向上阅读不被新消息拉走的行为；保留历史分页和草稿持久化。

删除后失去：重新打开时继续原阅读位置、恢复卡片展开状态。这是实际体验取舍，但不值得默认要求完整跨重启恢复协议。

可连带删：持久 anchor/offset/expansions、为恢复锚点服务的 around 查询和重试、相关 WorkspaceStore 缓存依赖。around 如还有真实用途则另行保留，不误删 before/after 基础分页。

## 4. 删除活动中心的流片级持久化和通知持久消费账本

**质疑的要求：所有实时活动细节都要落盘；通知发出前必须持久证明已经消费。**

证据：[activity-center.js:8](../src/main/conversations/activity-center.js#L8) 把 message_delta 纳入内容事件；observe 对事件更新 cursor/dirty 并 schedule，默认 100ms 窗口，flush 整体重写 rows。通知路径在 flush 成功后才 notify，notices、retiredEpochs 也进入持久数据。

建议：实时活动留内存，只保存已共识需要的最小重启摘要。通知只处理当前运行期的新事件，内存去重，启动恢复不发送历史通知；删除通知投递对活动文件落盘成功的依赖。

删除后失去：崩溃前精确的阅读/通知消费位置；不再保证最后极短窗口里的活动标记完整保留。保留默认关闭、仅后台通知、不抢焦点、点击打开等已认可产品行为。

与既有共识的关系：不整体删除 ActivityCenter，也不撤销“重启将任务摘要标为中断”。删除的是无跨重启必要性的高频细节和通知账本；保留关键任务摘要的低频保存。

## 5. 删除“可取消的优雅退出”功能及无界收尾流程

**质疑的要求：用户已经选择退出后，还需要取消退出、显示剩余任务数、重新打开窗口等待所有资源完成。**

证据：shutdown-coordinator.js（历史文件，已删除） 的 generation/cancel/failed 状态；[main.js:114](../src/main/main.js#L114) 退出超过一秒重新显示窗口；[main.js:1526](../src/main/main.js#L1526) 等待面板命令、删除操作和资源完成。

建议：删掉取消退出、退出进度状态机与强制重新显示窗口。采用一次有上限的 best-effort 停止和必要状态保存，然后退出。原审查提出过，本轮给出明确删除建议，但尚未在会话中对齐。

删除后失去：退出中反悔并留在应用、等待所有外部操作完成的保证。崩溃恢复并不修复外部操作，文档不能承诺；退出预算和超时后的具体处理在实施时明确，不用无限等待补足无法兑现的保证。

托盘创建失败也不应拒绝关窗，可走相同退出路径。关闭即隐藏的正常行为保留。

## 6. 整体删除 PanelCommands 命令状态机

**质疑的要求：打开、关闭、刷新一个面板，需要独立的命令 ID、revision、queued/running/completed 状态和查询 IPC。**

证据：panel-commands.js（历史文件，已删除） 为三种操作构建命令状态；[main.js:1472](../src/main/main.js#L1472) 接入。renderer 的 showPanelCommand 已无实际展示（前轮确认）。request 在任一操作进行时，将不同的新操作也当 existing 返回。

建议：在已确定移除 Foundry 锁和面板展示空壳之后，连 PanelCommands 整体删掉，三个 IPC 直接调用实际操作并返回结果。只保留已证明需要的同一操作 Promise 合并，不给面板按钮建立任务系统。

删除后失去：面板命令独立排队、查询其阶段和统一命令身份；普通打开/关闭/刷新及其错误反馈仍存在。不能简单删除模块而遗失原本只能通过完成事件传递的操作错误。

这是依赖既有共识的扩展，不重复把 recoveryBarrier/showPanelCommand 计为新发现。

## 7. 直接删除无生产消费者的增量回放缓存

**质疑的要求：主进程需要保存最近 256 条事件，供客户端按游标增量拉取。实际没有这样的生产消费者。**

证据：[session-projection.js:80](../src/main/sync/session-projection.js#L80) 的 sync() 仅在 session-projection.test.mjs 中调用，src 下未发现调用；publish 仍持续保存 events。当前 renderer 的 resyncSelected 请求的是完整快照。

建议直接删：sync()、events 环形记录和仅为它服务的 capacity 配置/校验/测试。保留 snapshot()、正在流式生成的内容，以及生产路径仍使用的事件身份。

删除后不损失现有生产能力。这不是先前的 renderer snapshotCache，是主进程另一份无消费者的事件缓存。

同批可清理：AgentHost.buildHistory → HistoryIndex.all 在 src 中无生产调用者；ActivityView 的 stateLabel、activeStates、items/notices、旧 activity-list/activity-toggle 引用等历史残留。不要顺带删除仍承担摘要同步和待处理标记的 ActivityView 全部代码。

## 次优先级：可以删，但收益小于上述项目

- loadPageWithRetry：新增 15 行瞬时错误白名单和立即重试一次。质疑“本地页面加载失败必须后台马上重试一次”；已有失败页面和用户 F5，未找到该重试的单独收益比较。可以回到单次加载和明确失败，但不删除页面导航/销毁异常处理。
- 跨重启的工具卡展开状态是第 3 项的一部分，不能另算一项收益；快照称重也不能在已有共识之外重复计数。

## 本轮不建议一并删除

- ExecutionScheduler：现有共识认可等待用户时释放并发槽。取消全局并发上限是另一项产品取舍（请求并发与费用暴露），本轮不借“删除锁”自动撤销。
- 历史分页：0.4.3 使用全量 buildHistory，main 改为页内返回；删除精确锚点恢复不要求退回一次渲染全部历史。
- 正在执行的 host、未保存草稿与事件衔接：不是可重新读取的快照缓存，不能沿用缓存结论整块误删。
- 多会话遥测隔离：增量为同时执行的会话区分关联上下文，共享 writer；如果保留遥测，不能退回按模式混记任务。
- 离线模块构建/本地 ZIP 安装：增量体积主要包括构建器和 vendored 依赖；现有文档给出实际离线构建安装消费者。不能因文件多就当成防御式冗余。是否取消该产品能力需要另一个需求判断。
- 上游编辑工具的校验、IPC 权限和文件路径安全：已有边界原则仍适用，不把删除应用级资源锁扩展成删除真实边界。

## 建议顺序

先删第 7 项无消费者代码；随后按产品价值讨论第 1–4 项。第 6 项跟随 Foundry 锁清理，第 5 项单独改变退出体验。实施时同步删除为已取消能力设立的规格要求和测试，保留对剩余用户行为的验证。新建议被接受后再进入共识文档，不因本次审查自动成为已定需求。
