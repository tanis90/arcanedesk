## 证据1：DeepSeek三张新卡，同一个技能漏洞

A1运行 benchmark-1788942865994，写入调用 call_00_C7mrrJOw2kcPt6mZEr0Z3288：

~~~js
skills: {arc: {value: 1}, inv: {value: 1}}
~~~

最终校验调用 call_00_kWYLW1IPFnooJhw83yRu6419：

~~~js
skills: {arc: s.skills.arc.value, inv: s.skills.inv.value}
~~~

结果熟练值确实为1，但真实卡上奥秘/调查的ability都是dex。A2对运动/察觉、A3对洞悉/宗教重复同一模式。这不是缺少“法师有什么能力”的规则，而是写入与自验共用错误假设；查询工具没有覆盖这层NPC字段语义。

A1第6次调用已经查询成长，第18次才写卡；第8–12次继续查包、特性、子职，后面又探查NPC schema与现有NPC。写入后还有8次browser_evaluate，多数涉及活动结构。大量工作发生在查询结果之外。

## 证据2：Qwen狼人，已返回的能力被主动省掉

B1运行 benchmark-1788945038104。查询返回明确包含：

- 五级ItemGrant：额外攻击，UUID Compendium.dnd5e.classfeatures.q9g1MLXuLZyxjQMg。
- 起始力量/体质豁免。
- 从合法池选两个技能。

最终模型却写：“未添加额外攻击（避免与原始多面攻击叠加）”。共用skill的原意是不要把额外攻击次数加到Multiattack上，模型理解成省略能力本身。这是我们说明容易误读的地方，工具补更多同样资料不能解决。

技能写入还多次使用proficient字段，之后才尝试value。调用call_6777e0b601d245c3bc1f034d、call_056a7131ea4343e7bd523878、call_ef24976a6622445b953459aa、call_994eecf449734b988e49de60可见这一修补过程。最终仍有技能关联属性错误。

## 证据3：Qwen地精，知道缺什么却停止

B2运行 benchmark-1788945762605。工具返回Dex/Int豁免、四项技能、两项专精候选及偷袭2d6。最终回复明确承认：

- Trait advancement不会自动配置，豁免仍为0。
- Expertise需选两项，未配置。
- 职业技能等选择未应用到NPC。

但仍以“NPC创建成功”结束。因此不是模型没看见要求，而是完成标准没有贯彻：把没有自动执行的正常配置，与本轮排除的复杂战斗自动化混在了一起。现有工具返回保留primary/secondary等原始条件，仍需模型自行把项目的“首次追加职业”默认映射到操作。

## 证据4：Qwen兽人，把追加任务做成重新车卡

B3运行 benchmark-1788946459829，写入调用call_91ee55cc132e444ebcc0ba1a将六项属性改成10/12/15/14/13/8；源兽人为16/12/16/7/11/10。不是只应用正常ASI。模型随后按这个错误的体质重新算HP，导致局部计算自洽，却偏离“保留原属性”要求。

最终回复承认准备法术仅3/7、未单独添加子职特性，仍结束任务。queryBuild参数只有className/level/raceName/rules，没有选定subclass和sourceActor上下文；当前返回不能直接识别此次属性重写或给出完整子职增量。

## 工具与skill之间的真实接口问题

queryBuild实现优先选择dnd5e原生职业来源，返回其ItemGrant UUID。模型同时读到的arcane-actor-update skill却要求职业能力优先从auto pack拿。因此“拿到成长UUID”之后仍去auto pack重新找同类能力。DeepSeek A1轨迹确实发生了这一轮重复工作。两条策略各有理由，但接口没把“成长依据”和“实际导入来源”接起来。

另外，成长skill有“不要扩展可选spellbook工作”的旧轻量NPC措辞，character-benchmark又要求完整法术列表并声明优先级。Qwen A3/B3都实际读取了这些skill。它们可能促成缩小范围的行为，但仅凭轨迹不能确定因果；应先消除这种指令张力，再比较。

## 针对性的下一步假设（尚未实施/验证）

1. skill明确区分“必须落实的普通字段/必选项”和“不要求实现的战斗自动化”；不能用已知未完成项替代交付。
2. 指定保留怪物原属性、单独保留Extra Attack能力但不叠加Multiattack次数，避免含混。
3. NPC API指南提供经验证的技能更新与有效值回读方式；自验比较期望与实际，不只列出写过的字段。
4. 查询工具若继续迭代，应先补选定子职、可执行来源映射及适用选择的清晰表达；暂不扩成完整车卡引擎。
5. auto pack不修改。这里是客户端查询/说明的兼容问题；包侧标识规范化需求继续仅记todo。
