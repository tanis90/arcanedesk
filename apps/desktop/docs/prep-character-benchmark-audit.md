# 六题 benchmark 验收修订记录

本轮是验收器试跑。模型输入保持冻结；修订在留存快照上重判，不重跑模型、不替模型修卡。原 v2 分数保留。最终结果使用同一版修订验收器，不能引用下面的阶段性通过数代替最终成绩。

| 问题 | 证据与修订 | 边界 |
| --- | --- | --- |
| auto pack 能力被误报缺失 | 实卡能力 identifier 为空或带前导连字符，但 compendiumSource 指向真实能力；按核实后的来源 UUID 建别名表，资源用对应 Item ID 读取 | 不按名字相似就放行，不改 auto pack |
| NPC 人类被误报无种族 | NPC `details.type` 为 humanoid，subtype 为人类；接受此表示，属性和移动独立检查 | 丘陵矮人还需对应矮人体魄来源；不只凭 subtype 认定全部种族能力完成 |
| 已选子职/战斗风格仍要求选择说明条目 | 已挂接正确 subclass 或具体战斗风格时，不要求重复导入选项容器 | 实际授予能力仍逐项检查 |
| NPC 生命领域要求 PC 护甲熟练字段 | 本地 dnd5e 5.3.3 对 NPC 武器/护甲熟练原生返回 1，NPC 不具有 PC 的 armorProf 数据模型 | 接受系统行为，不要求添加无效字段；不认证全部职业动作自动化 |

| 系统 gear 迁移被判内容破坏 | 狼人 Spear 仅新增 gear；dnd5e 5.3.3 源码存在该迁移 | 只在复制内容比较中排除 gear，不忽略其他 properties |
| 漏检越级能力和法术获取数量 | Qwen 五级法师拿了十级强效塑能；DeepSeek JS 五级法师有三个三环法术 | 识别已审核能力等级；法师按正常升级获取数量上限检查，无额外抄录 |
| 漏检技能关联属性 | DeepSeek A1 工具卡的奥秘、调查关联 dex；Qwen B2 部分非敏捷技能也变成 dex。旧参考 A 组三张卡存在同类问题 | 新增默认技能属性检查；B 组保留原卡明确覆盖。原样快照保留，另建修正参考卡，不修模型卡 |

## 技能默认的具体陷阱

本地 `dnd5e.mjs` 的技能 MappingField 中，通用记录 schema 的 `ability` 默认是 `dex`，而 `_initialSkillValue` 会按技能键填入对应的默认属性。如果只提供 `{value: 1}` 这样的部分技能记录，不能想当然地认为最后一定得到该技能正常的关联属性。实卡的原始字段和有效字段均确认了错误，验收必须读回最终关联属性。

这解释了为什么此前 DeepSeek A1 工具组会“通过当前检查”，但新增检查后不再全通过：来源识别误判确已解决，同时旧断言漏掉了另一项真实缺陷。参考创建器也出现了同样问题，说明正例本身需要独立检查，不能靠创建器与验收器相互证明。

离线回归保留该真实错误，并只在内存副本中纠正技能属性，以分别验证“合法来源表示可接受”和“错误技能配置会失败”。不会将修正副本冒充模型产物。

## 用户修订：不以升级历史判整题失败

用户指出任务重点是可用的目标等级卡，而非还原逐级车卡历史。spells.acquisition 改为 diagnostics，不参与 configurationPass 或计时成功。五级法师仍检查14个不同本书法术、4戏法、最高三环、适用职业、正确准备数量、法术位和火球活动；三个三环法术不再单独导致失败。新增合法三环选择的回归，确认会提示但不拒绝。规则上的升级新增与长休更换准备仍是不同机制；本修订是任务验收范围调整，不是改写2014规则。

同一v3重判已应用到全部已留存试次，DeepSeek A1 JS因此通过当前自动配置检查。已结束的首轮共用输入保留原样；后续默认skill已同步，新旧输入不能混算。
