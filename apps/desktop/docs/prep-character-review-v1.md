## 已验证到哪里

六张卡当前已编码的 core / important 检查全部通过。每项 expected / observed 存在 JSON 中。另有 **6个真实正例、22个反例**：在快照副本中删除职业/子职能力、破坏火球活动、加入高环法术位、取消准备、修改资源、移除源物品/免疫、修改源数据等，均被对应检查抓住。反例没有写入世界。

已实际读回：NPC 的原生 class/subclass Item 和累计等级、有效属性/HP/熟练/移动、法术位、法术准备数量、火球活动、装备、部分职业资源，以及追加题的原物品/效果/重要特征保留。源怪物在复核时重新读取，比对创建前快照，不依赖创建器早先保存的“after”。来源 UUID/hash 已记录。

这证明这些断言能够落地、能拒绝对应错误。它**不能证明整张卡没有遗漏，或所有技能自动化都能在实战中工作**。A1、B1已经打开并目视检查主卡，截图和完整数据留在本机实验目录。

## 先请 DM 审这几件事

1. **打开卡直接用，会被什么卡住？** 缺法术、消耗不对、某个能力只有说明，分别是否可接受。当前条目与部分资源有机器检查，实际攻击/治疗/重击/豁免联动没有认证。
2. **追加等级的尺度是否合适？** B1的HP98、B2的22、B3的50；保留怪物属性，仅加正常ASI。是否符合你说“给它五级职业”的默认期待。
3. **什么属于可随后补的小缺口？** 普通起始背包、弹药、施法圣徽/材料、语言/技能选项、种族抗性等目前没有完整自动验收；样例也不应被当作这些方面的全量答案。请指出哪些会让你认为“这张卡还不能交付”。

具体发现：狼人卡生命骰显示14（原9加职业5），有效HD面数仍为d8，HP公式仍是原`9d8 + 18`，而HP最大值为98。当前没有评估混合生命骰、重掷公式和休息行为；要先决定追加题要不要要求这些一致。不要把这一点藏在“HP检查通过”后面。

当前权重只是可审阅草案：明确需求、职业等级/能力、施法资源、保留原内容优先；移动/装备/技能/部分职业资源放第二层。不把你的判断强行转成权重分数。你指出具体卡上的问题后，再决定某项是阻断交付、次要缺陷，还是本轮排除。

## 冻结前仍需完成

- 根据实卡反馈调整默认、合并策略和优先级，并修订样例与断言。
- 当前断言部分绑定了本次技能/装备/AC选择，未来模型可以做另一套合法选择，必须改成合法集合和派生关系再评分。
- 当前要求原生职业Item，尚未覆盖文档允许的其他等价NPC表示；不能无说明地把此限制当作模型失败。
- 职业成长完整性、种族效果、法术列表及逐级选法合法性仍需补足或明确排除；来源正确/条目数量正确不等于这些全正确。
- 冻结后才启动两组同默认的模型计时实验。CR继续不评分；涉及 auto pack 的改造只记 todo，不修改包。
