## 失败与慢调用的含义

1. 多数已核对的失败发生在写入或最终验收：标准数组/种族/ASI、HP、步速、技能ability、法术数量。Qwen B2把d6平均值提前取整，A3把子职classIdentifier写成life-domain并首匹配到残暴轻锤，均有实际脚本证据。
2. “多写一些知识”不是通用解：技能ability、子职关联、HP最终取整、法术书数量在共用skill中已有说明，模型仍未执行到位。步速则缺少专门字段条目，应区分缺失与未落实。
3. 来源查询后仍会探索系统实现。DeepSeek工具组A2有12次PowerShell源码查询；B3有23次、31.447秒，涉及成长管理、施法等级、熟练和准备法术。不能将总耗时减工具执行时间直接称为thinking时间。
4. 尚无证据证明这些写错问题必须增加一层自定义Actor JSON才能解决。也不能因查询本身通过了只读审查，就假设模型拿到信息一定写对。
5. A1 Qwen工具组的卜筮术（来源含TCE可选扩展）及默认mage AC属于合同/验收歧义，原始判分保留、人工意见分列。即使放行这两项，属性和HP仍导致该次失败，因此不改变上述通过率。字段失败数不当作独立根因数，例如错误子职关联会连带额外熟练判分。

## 下一轮建议与边界

先冻结本轮作为基线，不继续无差别扩张查询输出或增设写工具。优先验证一项小范围假设：把已验证的原生API写法和末次验收组织成短流程，能否减少实现探索与漏验，同时保留模型校验能力。

- 保留来源读取、待选项和原生Document API路径；补步速字段，将已存在的技能ability、子职关联、最终HP取整、法术数量检查放到同一次写后读回中。
- 验证应比较独立预期与有效字段，并返回不一致；不能只读回自己写下的值，也不能要求盲信工具。
- 先解决A1的可选规则和默认护甲合同歧义，再以新版本重新运行受影响案例；旧成绩不覆盖。
- 复测应兼顾失败与回归：A1/A3从零配置、B2取整、B3源码探索，以及B1已获收益的守护案例。采用同模型/供应商/设置的交错重复，先看正确完成率，再看双方成功时间和往返。
- 本轮没有启动下一轮改造或重复实验。若后续只能靠逐题特例、持续增大上下文或减少真实验收来变绿，应停止该改造方向；不能用更少调用交换更多返工。
