# 多会话规格验收审计

日期：2026-09-07。审计代码基线：`26776eb`。依据：[spec](spec.md)、[architecture](architecture.md)。

结论：整体未完成。执行与视图分离、受控并发、现场恢复和真实进程重启已有证据；M8i–M8l 已修复并自动化验收 G1–G5。G6 生产联合场景及 G7 系统展示/实际 Foundry 操作仍需要更强的集成证据，之后还需最终性能与规格复核。

后续状态更新：下列表格保留 `26776eb` 的审计定位，其中 G1/G2 已由 M8i 关闭，G3 已由 M8j 关闭，引用这些编号的条款按本段更新判断。新增可见发送语义和可访问名称；停止请求及执行侧 stopping 均保护草稿/附件，阻止发送与重试；失败回执、跨模式、刷新及旧任务迟到回执由 E3 新断言验证。M8j 从实时事件和快照统一重建终态原因及下一步，E3 验证后台失败打开、刷新、去重、文本转义及恢复草稿；未提供原因时明确说明。G4–G7 仍待完成。

M8k 更新：G5 已关闭。controller 检查当前 activeHost 而非只依赖已启动缓存；空选择恢复优先选中存活 resident。E7 新断言验证删除替代启动失败后的重复恢复与并发合并；E1 生产 IPC 验证删除 A 后恢复原 B 的同一个 SDK 实例，运行不中断、请求不重复。尚待 G4、G6/G7 及最终复核。

M8l 更新：G4 已关闭。缓存现场明确等待校准，只有新快照或连续实时事件更新最后确认时间。同步超过一秒提示，快照请求十秒超时后可重试；活动任务静默十五秒后由五秒检查周期触发只读快照，不能以静默推断终态。E3 新断言覆盖缓存时间不变、迟到失败、重新进入同一会话的新请求、失败/挂起/重试、静默探测与零模型提交；E5 长历史最终独立及三次连续验收通过。性能基准需在最终实现稳定后复核。

M8m1 更新：G6 的真实长工具/跨模式/刷新及停止隔离子场景已通过 E13。验收发现并修复实时事件与快照使用不同工具计时时钟的问题；开始/结束时间现在由执行侧统一发布。G6 的模型/目录联合、自动重试、乱序及实际 Foundry 场景仍未全部完成。

M8m2 更新：G6 的模型/目录联合场景通过 E14，修复了默认模型仍会覆盖已有空会话的问题。A/B 原生会话目录独立；不同模型及 B 下一任务的模型选择由实际 HTTP 请求验证。非默认 provider 补齐密钥会激活已选择它的空闲会话，不覆盖其他会话。G6 仍有自动重试、乱序及实际 Foundry 场景待完成。

M8m3 更新：G6 自动重试通过 E15。修复 renderer 缺少重试提示，以及 SDK 重试请求再次发出 agent_start 时投影提前清除阶段的问题。实时事件和刷新快照均保留重试次数，SDK 明确结束或任务边界才清除；等待中停止不发起后续请求，另一任务不受影响。乱序导航、实际 Foundry、G7 平台交互及最终性能仍待完成。

M8m4 更新：G6 生产页面乱序导航与快照/终态边界通过 E16。修复侧栏点击使用列表生成时的 active 和 sessionId，导致缓存切换后立即点回原会话被忽略的问题。导航按当前选择和有效模式判断，在点击时捕获最新上下文；迟到 B 回包不能覆盖后选中的 A。实际 Foundry、G7 平台交互及最终性能/规格复核仍待完成。

M8n1 更新：G7 的 Windows 原生关闭/取消、最小化/恢复、停止退出已经实际系统输入验证，见 [原生验收记录](windows-native-acceptance.md)。未关闭系统托盘实际点击、通知或多尺寸布局部分。同时发现普通会话列表的首轮标题/数量滞后，新增 G9；不能以活动区正确代替会话列表正确。

M8n2 更新：G9 已关闭。驻留会话列表从原生 SDK 内存日志计算首条用户文字和消息数，消除首轮磁盘滞后；前端在输入消费、消息完成和执行结束时合并更新原有行。E17 验证前台首轮、后台完成、抽屉打开时的计数更新与行身份/顺序不变。
